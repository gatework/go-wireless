# v0.6.0

本版本修复控制器回显进入类型模型时的数据缺失，区分射频运行状态与管理状态，并升级正式依赖。Go 调用者和共享清单配置需要迁移。

- 传输依赖迁移到正式发布的 `github.com/gatework/net-connector v0.9.0`，共享运维依赖升级到 `go-netops v0.4.0`；原 `go-net-connector` 导入路径需要迁移。
- 同步更新 pgx v5.13.0、x/term v0.48.0 和 x/text v0.44.0，最低 Go 版本保持 1.26.0。
- 清单筛选改为 `include_platforms` / `exclude_platforms`，平台覆盖改为 `platform_overrides`，`device_rules[].connector` 改为 `device_rules[].platform`；对应环境变量改用 `PLATFORM`。
- 共享 SSH 配置中的 `vendor_protocols` 改为 `platform_protocols`；Wireless 仍只继承主机信任设置，控制器连接使用 SSH。
- 注册表接口改用 `net-connector/platform.Registry`，清单解析使用 `Record.Platform`；原始 Netdisco `Device.Vendor` 字段保留。
- 控制器和 AP 查询仍受选定 profile 约束，已接受回执与后置清理错误分别保留，不自动重放、重连、回滚或保存配置。
- `wlan.Settings` 补齐嵌套 VLAN 与已确认的 H3C 配置语法；服务模板可以保留具名 Portal 服务器。`Portal.ApplyWebServer` 与 `ApplyMACTriggerServer` 改为 `*ServerReference`，JSON 仍使用字符串、存在性布尔值或 null；URL 名称在读写两端被拒绝，错误不会携带原值。
- 射频 `State` 写入 `OperationalStatus`；只有明确的 `Admin state` 才写入管理状态及来源。旧报告来源不明的管理状态不触发管理 Down 判断；AP、射频和历史冲突规则要求对应维度完整。
- 使用正式 parser v0.2.2 保存原始行、摘要和捕获范围。输入先接受 32 MiB、400,000 物理行预算检查，超限整体失败；不截断后继续解释。该预算保留现有超过 16 MiB 的离线证据文件能力。
- 补齐 AP MAC、负载均衡、全局热备、射频客户端拒绝和漫游导航，以及客户端 Radio slice。数量不符、空正文和历史重复事件继续保留诊断；私有语料回放入口为 `make corpus`，原文不进入仓库。

API 迁移与证据边界见 [核心 API](../core-api.md#runtime-evidence-corrections) 和 [验证说明](../verification.md)。

最低 Go 版本保持 1.26。模拟会话、冻结语料和独立消费者验证不代表真实控制器验收。
